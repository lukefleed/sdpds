The framework analysis (\S\ref{sec:framework}) establishes that dynamic mutability and algebraic composability impose conflicting requirements on oracle state representation. Mutability requires element-level information retention to enable targeted deletion. Composability requires information loss through commutative aggregation operations. This tension generates three research directions: determining whether any structure can provide both properties optimally, evaluating hybrid system designs that provide both properties sub-optimally, and analyzing how security, privacy, and fault tolerance constraints interact with the core property requirements.

\subsection{Structures with Dual Properties}
\label{subsec:dual-properties}

The framework establishes (\S\ref{subsec:core-properties}) that mutability requires element-level information retention while composability requires lossy compression through commutative operations. This formulation poses a constraint satisfaction question: does any state representation exist that permits both targeted deletion and order-independent aggregation without sacrificing optimality for either property?

The structures examined provide evidence supporting a negative answer. The Cuckoo Filter (\S\ref{subsec:cuckoo-filters}) stores explicit fingerprints, enabling constant-time deletion but preventing composability; merge operations must track element provenance to avoid double-counting. The HyperLogLog sketch (\S\ref{subsec:hyperloglog}) discards element identities through register-wise maximum operations, enabling composability but preventing deletion; no mechanism exists to identify which elements contributed to a register's current value. The Counting Bloom Filter attempts to bridge this gap through auxiliary counters but fails to achieve composability; counter subtraction is not idempotent, violating the fault-tolerance requirement for distributed aggregation.

We identify two research questions. First, can a proof establish that no structure simultaneously achieves constant-time deletion and idempotent merge operations without sacrificing space efficiency? Such a proof would demonstrate that the mutability-composability dichotomy reflects an information-theoretic lower bound rather than an artifact of current algorithmic techniques. Second, if unified structures necessarily sacrifice optimality for at least one property, what are the achievable trade-offs? A unified structure might provide logarithmic-time deletion and composability, or constant-time operations for both properties with increased space overhead. Characterizing this trade-off space constitutes the second research direction. The decision framework (\S\ref{subsec:decision-framework}) identifies workloads that require both properties, such as distributed databases that must aggregate cardinality estimates while tracking element deletions.

\subsection{Hybrid Systems for Dual Requirements}
\label{subsec:hybrid-architectures}

If no unified structure can provide both properties optimally, systems requiring both properties must employ hybrid architectures. Two strategies exist. The first maintains separate specialized oracles: a Cuckoo Filter for membership testing with deletion support, and a HyperLogLog sketch for cardinality estimation with distributed aggregation. This separation preserves per-property optimality at the cost of doubled memory overhead and synchronized updates. Redis implements this approach through distinct command sets for HyperLogLog and Cuckoo Filters \cite{redis-hll, redis-cuckoo-filters}.

The second strategy employs a unified structure that provides both properties sub-optimally. Evaluating this approach requires characterizing the trade-off frontier: for a given space budget $s$, what deletion time $t_d$ and merge time $t_m$ can a unified structure achieve compared to the dual-structure baseline of $(t_d^*, t_m^*, 2s)$? A unified structure is viable if it achieves $(t_d, t_m, s)$ where $\max(t_d/t_d^*, t_m/t_m^*) < 2$, providing comparable performance with half the memory footprint. Establishing this frontier requires systematic evaluation across workloads with varying insertion rates, deletion rates, and aggregation frequencies.

\subsection{Orthogonal Challenges Beyond the Dichotomy}
\label{subsec:orthogonal-challenges}

The mutability-composability dichotomy addresses two deployment constraints: state synchronization with evolving datasets and distributed aggregation without data shuffling. Distributed oracle deployment introduces three additional constraints that impose requirements orthogonal to these core properties: resistance to adversarial manipulation, privacy preservation under observation, and fault tolerance for stateful computation. We analyze whether these constraints generate new properties or modify existing property requirements.

Security against adversarial inputs requires verification mechanisms that may conflict with oracle compactness. The cardinality inflation attack (\S\ref{subsubsec:hll-security}) demonstrated by Reviriego et al. exploits the deterministic hash-to-register mapping in HyperLogLog; an adversary constructs inputs that maximize register values, producing inflated estimates from minimal insertions \cite{Reviriego2020HyperLogLogS}. Mitigation through cryptographic salts breaks composability across administrative domains; sketches using different salts cannot be merged. Byzantine-resilient aggregation rules, such as the Geometric Median, filter malicious updates but require transmitting multiple candidate sketches rather than a single merged sketch, increasing communication cost \cite{Le2025ByzantineRF, Kuwaranancharoen2023OnTG}. This tension suggests a new property requirement: aggregation rules must be both composable and robust to outliers.

Privacy preservation requires bounding information leakage from oracle state. Le et al. demonstrate (\S\ref{subsubsec:hll-privacy}) that HyperLogLog sketches enable linkage attacks; an observer of transmitted sketches can infer properties of unique individuals in rare-disease queries \cite{Le2025ByzantineRF}. Ensuring k-anonymity requires that each bucket's value could have been generated by at least k individuals from a background population. This constraint conflicts with the accuracy requirement; higher precision (more buckets) improves cardinality estimates but reduces per-bucket anonymity. Differential privacy mechanisms add calibrated noise to oracle state, but this noise addition must commute with merge operations to preserve composability. This interaction between privacy and composability represents an open research direction.

Fault tolerance for stateful streaming computation requires bounding error accumulation under failures. The AF-Stream protocol (\S\ref{subsubsec:hll-fault-tolerance}) uses adaptive checkpointing; backup operations trigger only when state divergence exceeds a threshold, trading checkpoint frequency for bounded error \cite{Huang2016TowardHD}. This approach relies on idempotency; duplicate sketch transmissions during retries do not corrupt aggregate state. However, adaptive checkpointing does not extend to oracles lacking composability. A Cuckoo Filter cannot bound error accumulation through threshold-based backup; a missing deletion operation introduces permanent state divergence. This suggests that fault tolerance protocols depend on whether the oracle satisfies composability, creating an asymmetry in recovery mechanisms for the two property classes.
