In the two previous sections we derived two properties from distributed deployment constraints. Section~\ref{sec:membership} established dynamic mutability (Definition~\ref{def:mutability}) as the requirement for state synchronization in systems where datasets undergo deletion. Section~\ref{sec:cardinality} established composability (Definition~\ref{def:composability}) as the requirement for distributed aggregation without data shuffling. We observe that these properties address orthogonal constraints: mutability maintains oracle consistency with evolving datasets, while composability combines partial results across network-separated partitions. This section analyzes the implications of this orthogonality for structure selection and deployment.

\subsection{Mutability-Composability Orthogonality}
\label{subsec:core-properties}

Dynamic mutability and composability address distinct requirements. A membership oracle for a dynamic dataset requires mutability regardless of whether the oracle is replicated or partitioned. A cardinality oracle for a static dataset requires composability if the dataset is partitioned, regardless of whether elements are ever deleted. The constraints impose requirements on different aspects of oracle functionality: mutability constrains the update interface, while composability constrains the merge interface.

The mechanisms enabling these properties impose conflicting requirements on state representation. Mutability requires retaining sufficient information to identify and remove a specific element's contribution. The Cuckoo Filter achieves this by storing explicit fingerprints in buckets at deterministically computable locations (\S\ref{subsec:cuckoo-filters}). Deletion locates the fingerprint and erases it without affecting other entries. This explicit storage enables constant-time deletion without false negatives.

Composability requires that oracle state be derivable from commutative operations applied to element representations. Such operations necessarily lose information about individual elements. The HyperLogLog sketch (Definition~\ref{def:hll-sketch}) achieves this by retaining only maximum observables in each register, discarding element identities (subsection~\ref{subsec:hyperloglog}). The register-wise maximum operation used for sketch union cannot distinguish which specific elements contributed to a register's current value. This information loss enables order-independent aggregation.

A structure that retains sufficient information for targeted deletion cannot perform order-independent aggregation, as the merge operation must track which elements have been processed to avoid double-counting. Conversely, a structure that performs order-independent aggregation through lossy compression cannot support targeted deletion, as the information required to identify a specific element's contribution has been discarded. This reflects a trade-off between maintaining element-level granularity and achieving compression through information loss.

\subsubsection{Structural Incompatibility}

We establish that idempotent merge operations preclude the information retention required for deletion without false negatives under specific constraints on oracle design.

\begin{definition}[Reversible Element Representation]
    An oracle $\mathcal{D}$ maintains a reversible representation of element $x$ if there exists a deterministic procedure that, given $x$ and the current state of $\mathcal{D}$, identifies a set $L_x \subseteq \text{State}(\mathcal{D})$ of memory locations such that: (i) $L_x$ contains all and only the locations whose values were modified by the most recent insertion of $x$ into $\mathcal{D}$. (ii) There exists an operation $\textsc{Remove}(x, \mathcal{D})$ that modifies only locations in $L_x$ such that for all elements $y \neq x$ with $y$ currently represented in $\mathcal{D}$, the probability $P(\mathcal{D}.\textsc{Query}(y) = \text{true})$ after removal equals the probability before removal.
\end{definition}

The Cuckoo Filter satisfies this definition. The procedure computes the two candidate bucket indices $i_1 = h(x)$ and $i_2 = i_1 \oplus h_f(f)$ where $f = \textsc{fingerprint}(x)$, then searches for $f$ in those buckets. The set $L_x$ consists of the single slot containing $f$. Removing $f$ from that slot does not affect other stored fingerprints. The HyperLogLog sketch does not satisfy this definition. An element $x$ contributes $\rho(h(x))$ to register $M[j]$ through the update $M[j] := \max(M[j], \rho(h(x)))$. No procedure can determine from $M[j]$ alone whether the current value was contributed by $x$ or by another element $y$ with $\rho(h(y)) \geq \rho(h(x))$.

\begin{lemma}[State Indistinguishability Under Idempotent Merge]
    \label{lem:indistinguishability}
    Let $\mathcal{D}$ be an oracle with a merge operation $\cup$ that is idempotent in the sense that for any state $s \in \text{State}(\mathcal{D})$, we have $s \cup s = s$ (syntactic equality of internal state). Let $s_1$ be the state after inserting element $x$ once into an empty oracle, and let $s_2$ be the state after merging $s_1$ with itself. Then $s_1 = s_2$, and thus the oracle cannot distinguish between one insertion and two insertions of the same element based solely on internal state.
\end{lemma}

\begin{proof}
    By idempotence, $s_1 \cup s_1 = s_1$. If we denote by $s_2$ the result of this merge, then $s_2 = s_1$ syntactically. Therefore, the oracle's internal state after one insertion is identical to its state after merging that state with itself, which would represent the union of two sets each containing $x$. The oracle has no mechanism to distinguish these cases from its internal representation alone.
\end{proof}

\begin{lemma}[Deletion Requires Local Element Information]
    \label{lem:deletion-locality}
    Let $\mathcal{D}$ be an oracle representing a set $S$, and suppose $\textsc{Delete}(x)$ operates by modifying some subset of memory locations in $\textsc{State}(\mathcal{D})$ without access to auxiliary data structures. If the oracle does not maintain information allowing it to identify which locations were modified specifically by inserting $x$, then one of the following must occur: either $\textsc{Delete}(x)$ modifies locations that may have been set by other elements $y \in S \setminus \{x\}$, introducing false negatives for those elements, or $\textsc{Delete}(x)$ fails to modify all locations set by $x$, allowing false positives for $x$ after deletion.
\end{lemma}

\begin{proof}
    Consider a memory location $\ell$ in the oracle's state that was set to value $v$ by inserting $x$. Suppose that the oracle's representation is such that other elements $y_1, \ldots, y_k$ could also set $\ell$ to $v$ or to values indistinguishable from $v$. Without information identifying whether the current value of $\ell$ was contributed by $x$ or by some $y_i$, the deletion procedure faces a dilemma. If it modifies $\ell$ to remove $x$'s contribution, it risks removing contributions from $y_i \in S \setminus \{x\}$, causing queries for $y_i$ to return false despite $y_i$ remaining in the set. Conversely, if it leaves $\ell$ unmodified to preserve potential contributions from other elements, then queries for $x$ will continue to return true, violating the deletion guarantee. The only resolution is to maintain information at each location sufficient to attribute the current value to specific elements, which constitutes a reversible representation.
\end{proof}

\begin{theorem}[Incompatibility of Idempotent Composability and Deletion]
    \label{thm:incompatibility}
    Let $\mathcal{D}$ be a probabilistic oracle satisfying the following conditions:
    \begin{enumerate}
        \item[(1)] The merge operation $\cup$ is idempotent with respect to syntactic state equality.
        \item[(2)] The oracle does not employ auxiliary data structures; all information is encoded in a single internal state representation.
        \item[(3)] The oracle supports a deletion operation $\textsc{Delete}(x)$ executing in time independent of the number of elements represented.
        \item[(4)] For all elements $y$ currently in the represented set $S$, queries satisfy $P(\mathcal{D}.\textsc{Query}(y) = \text{true}) = 1$ before and after any deletion of $x \neq y$.
    \end{enumerate}
    Then $\mathcal{D}$ must maintain reversible element representations as defined above.
\end{theorem}

\begin{proof}
    Assume for contradiction that $\mathcal{D}$ satisfies conditions (1)-(4) but does not maintain reversible element representations. By Lemma~\ref{lem:indistinguishability}, the idempotent merge operation prevents the oracle from distinguishing between single and multiple insertions of the same element based on internal state alone. This implies that information about individual element contributions must be aggregated or compressed in a way that loses element-level granularity.

    Consider the state of the oracle after inserting elements $x$ and $y$ where both elements contribute to overlapping portions of the internal state. Specifically, suppose both $x$ and $y$ cause modifications to a memory location $\ell$, setting it to a value determined by some commutative, associative operation over their individual contributions. For the merge operation to be idempotent, this operation must satisfy $f(a, a) = a$ for all values $a$. Standard examples include $\max$, $\min$, or bitwise OR.

    When $\textsc{Delete}(x)$ is invoked, the operation must determine which locations to modify. By assumption (2), no auxiliary structure exists to record which elements contributed to each location. The oracle must decide based solely on $x$ and the current state. By Lemma~\ref{lem:deletion-locality}, without information attributing location values to specific elements, deletion must either modify locations potentially set by other elements $y \in S \setminus \{x\}$ or leave locations that would cause $x$ to remain queryable.

    In the first case, if deletion modifies location $\ell$ that was set by both $x$ and $y$ to value $v = f(c_x, c_y)$ where $c_x$ and $c_y$ are their respective contributions, then removing $x$'s contribution would require computing $f^{-1}(v, c_x)$ to obtain $c_y$. However, for operations like $\max$ that satisfy idempotence, the inverse is not uniquely defined: if $v = \max(c_x, c_y)$ and $v = c_x = c_y$, we cannot determine the original $c_y$ from $v$ and $c_x$ alone. Any modification to $\ell$ risks setting it to a value incompatible with $y$'s presence, introducing a false negative for $y$, violating condition (4).

    In the second case, if deletion leaves $\ell$ unmodified to avoid corrupting other elements' representations, then queries for $x$ computed from $\ell$ will continue to indicate $x$'s presence. This violates the deletion guarantee that $P(\mathcal{D}.\textsc{Query}(x) = \text{true}) \leq \varepsilon$ after deletion for $x \notin S$.

    Both cases yield contradictions. Therefore, the oracle must maintain sufficient information at each location to attribute values to specific elements, allowing $\textsc{Delete}(x)$ to identify and modify precisely the locations affected by $x$ without ambiguity. This is the definition of a reversible element representation. The assumption that $\mathcal{D}$ does not maintain such representations must be false.
\end{proof}

The Cuckoo Filter maintains reversible representations through explicit fingerprints stored in deterministically computable bucket locations, enabling constant-time deletion without false negatives for remaining elements. However, its merge operation is not idempotent: merging a Cuckoo Filter with itself duplicates all fingerprints, producing a state distinct from the original. The HyperLogLog sketch has an idempotent merge operation through register-wise maximum, but the maximum operation discards element identities, precluding deletion without reconstructing the sketch from raw data. Theorem~\ref{thm:incompatibility} establishes that this dichotomy is not a consequence of algorithmic limitation but an information-theoretic necessity arising from the incompatible requirements that idempotent merge and reversible representation place on state encoding.

\subsection{Deployment Patterns and Property Requirements}
\label{subsec:patterns-from-properties}

The orthogonality established in subsection~\ref{subsec:core-properties} enables a classification of deployment patterns based on which constraint they address. We identify two pattern classes and derive the property requirements that enable each class.

\subsubsection{Local-Execution Patterns}
\label{subsubsec:mutability-copartition}

\begin{definition}[Local-Execution Pattern]
    A distributed system of $N$ nodes implements a local-execution pattern if there exists a partitioning function $\pi: \mathcal{U} \to \{1, \ldots, N\}$ such that: (1) each data item $d$ is stored on node $\pi(d)$, (2) each oracle state component $c$ (such as a filter bucket) is stored on node $\pi(c)$, where the partitioning of oracle components aligns with data partitioning, (3) a query for element $x$ is routed to node $\pi(x)$, and (4) query execution requires only local state access on the responsible node, with no communication to other nodes.
\end{definition}

Distributed systems that align oracle partitioning with data partitioning enable local execution of oracle operations. A membership query for an element is routed to the node responsible for that element's partition, where both the data item and the oracle state are co-located. This eliminates network round-trips for oracle queries. The pattern applies to any workload where query routing can be determined from the queried element's hash value: membership testing in partitioned key-value stores, existence checks in distributed caches, and presence verification in content-addressable storage systems.

The viability of local-execution patterns is contingent upon oracle mutability. When data is deleted from a partition, the co-located oracle state must reflect this deletion to maintain consistency. Without deletion support, the oracle state diverges from the true partition contents. A query for a deleted element returns a false positive, forcing the system to perform a validation lookup against the backing data store. This validation lookup incurs the network round-trip cost that the oracle was designed to eliminate. As the deletion rate increases, the frequency of these wasted lookups increases proportionally, eventually negating the performance benefit of local execution.

The co-partitioning architecture (\S~\ref{subsubsec:co-partitioning}) instantiates this pattern class for membership testing. Filter buckets are assigned to the same consistent hash ring as data keys. Each node maintains both the data items and the filter buckets within its assigned token range. Theorem~\ref{thm:co-partitioned-latency} establishes that expected query latency is independent of dataset size under uniform query distribution. This constant-time guarantee holds only for oracles that support deletion, as element removal must not require accessing non-local state or rebuilding global data structures.

A local-execution pattern is correct for dynamic datasets if and only if the oracle satisfies Definition~\ref{def:mutability}. The Cuckoo Filter analysis in \S\ref{subsec:cuckoo-filters} demonstrates that deletion can be performed locally using only the element's fingerprint. Any oracle lacking deletion support accumulates stale positives proportional to the deletion rate, forcing validation lookups that violate the local-execution guarantee.

\subsubsection{Hierarchical-Reduction Patterns}
\label{subsubsec:composability-hierarchy}

Distributed aggregation systems organize nodes into reduction hierarchies where intermediate nodes combine partial results from children. The pattern manifests in multiple system architectures. MapReduce implements two-level hierarchies: map workers produce partial results, reduce workers aggregate these results. Stream processing systems implement temporal hierarchies: window operators maintain sketches for time intervals, aggregator operators combine sketches across intervals. Multi-datacenter architectures implement spatial hierarchies: regional aggregators combine results from local data centers, global aggregators combine regional results.

The correctness of hierarchical reduction is contingent upon merge operation commutativity, associativity, and idempotency. Commutativity ensures that intermediate nodes can merge results from children in any order. This permits load-balancing strategies where faster children's results are processed immediately without waiting for slower children. Associativity ensures that the final result is independent of tree structure. This permits dynamic tree reconfiguration in response to node failures or load imbalances without affecting correctness. Idempotency enables fault tolerance under at-least-once delivery semantics. A child's result can be retransmitted and merged multiple times during network failures without corrupting the aggregate state.

Under a crash-stop failure model, consider a reduction tree with $k$ leaf nodes and depth $d$. If an intermediate node fails after receiving partial results from $k'$ of its children, those partial results are lost unless persistent checkpointing is employed. The idempotency property allows recovery through replay: once the failed node restarts, children retransmit their results, and the merge operation produces the correct aggregate because $\mathcal{D}_i \cup \mathcal{D}_i = \mathcal{D}_i$ for any already-merged sketch $\mathcal{D}_i$. This guarantee holds under at-least-once message delivery, where the communication layer may duplicate messages but ensures eventual delivery. In contrast, non-idempotent operations require exactly-once delivery semantics, which impose higher coordination overhead and cannot tolerate certain classes of network failures.

The hierarchical aggregation architecture for cardinality estimation (\S\ref{subsubsec:hll-patterns}) instantiates this pattern class. Worker nodes construct HyperLogLog sketches over local data partitions. Intermediate aggregators merge sketches using the register-wise maximum operation. Theorem~\ref{thm:hll-union-properties} establishes that this operation is commutative, associative, and idempotent. Communication cost is $\Theta(ks)$ for $k$ worker nodes transmitting sketches of size $s$, independent of dataset cardinality $n$. This fixed-cost property transforms cardinality estimation from a communication-bound problem to a computation-bound problem.

A hierarchical-reduction pattern produces correct global aggregates if and only if the oracle satisfies Definition~\ref{def:composability}. The HyperLogLog analysis in \S\ref{subsec:hyperloglog} shows that the union of partial sketches is equivalent to a sketch constructed over the complete dataset. Without commutativity and associativity, the result depends on merge order. Without idempotency, duplicate transmissions corrupt the aggregate.

\subsection{Structure Selection Criteria}
\label{subsec:decision-framework}

Structure selection depends on two workload characteristics: data lifecycle dynamics and query result formation.

\subsubsection{Data Lifecycle Dynamics}

Static datasets perform insertion without deletion, as in append-only event logs, historical archives, and immutable data lakes. These workloads do not require mutability. Append-with-expiry datasets insert elements with time-to-live values that expire automatically. Time-windowed stream analytics, session stores with timeout, and caches with time-based eviction follow this pattern. These workloads maintain separate oracles per time window and discard entire oracles upon expiration rather than removing individual elements. This approach does not require element-level mutability.

Fully-dynamic datasets perform arbitrary insertion and deletion driven by application logic. Key-value stores with tombstones, caches with LRU eviction, and distributed hash tables with explicit remove operations exemplify this pattern. These workloads require mutability to maintain oracle consistency with dataset state.

\subsubsection{Query Result Formation}

Single-partition queries execute entirely within one partition, as in point lookups where routing directs queries to the responsible partition, range scans within a shard, and membership tests in node-local caches. These workloads answer queries using only local oracle state and do not require composability.

Multi-partition aggregation combines information across partitions. Global distinct counts from per-partition sketches, federated analytics across administrative domains, and datacenter-level cardinality estimates from server-level aggregates exemplify this pattern. These workloads require composability to merge partial results.

\subsubsection{Workload Classification and Structure Selection}

The intersection of data lifecycle dynamics and query result formation determines which property the oracle must satisfy. Fully-dynamic datasets with single-partition queries require mutability without composability. The Cuckoo Filter satisfies this requirement, enabling membership testing in partitioned key-value stores, filters for LSM-tree SSTables undergoing compaction, and Pending Interest Tables in named-data networking where elements are explicitly deleted but queries execute locally.

Static or append-with-expiry datasets with multi-partition aggregation require composability without mutability. The HyperLogLog sketch satisfies this requirement, enabling cardinality estimation in MapReduce batch jobs where data is immutable, real-time analytics over sliding windows where entire windows expire atomically, and multi-datacenter monitoring where sketches from regional aggregators merge without element-level deletion.

Fully-dynamic datasets with multi-partition aggregation require both properties. Theorem~\ref{thm:incompatibility} establishes that no single structure satisfies both properties optimally when deletion must operate on internal state and merge must be idempotent. Distributed databases that track deletions for membership queries while aggregating cardinality estimates, distributed caches that track invalidations while computing global hit rates, and collaborative analytics systems that remove sensitive records while maintaining aggregate statistics across administrative boundaries all confront this constraint. These systems require hybrid deployments maintaining separate specialized oracles: a Cuckoo Filter for membership testing with deletion support, and a HyperLogLog sketch for cardinality aggregation, with the overhead of maintaining two independent data structures.

Static datasets with single-partition queries require neither property. A standard Bloom filter, which lacks both deletion support and efficient merge operations, suffices for this workload class. This case falls outside the primary scope of the framework.

\subsubsection{Relaxations and Approximations}

Theorem~\ref{thm:incompatibility} establishes a binary constraint under strict requirements: perfect idempotence and zero false negatives during deletion. Relaxing these requirements may enable structures that approximate both properties within specified error tolerances. Consider deletion with bounded false negative rate: an oracle that permits $P(\mathcal{D}.\textsc{Query}(y) = \text{true}) \geq 1 - \eta$ for $y \in S$ after deleting $x \neq y$, where $\eta > 0$ is a small error parameter. Such relaxation may enable approximate composability where $\mathcal{D}_1 \cup \mathcal{D}_2$ produces estimates within $(1 \pm \delta)$ of the ideal single-pass estimate for a small $\delta > 0$. Similarly, weakening idempotence to $P(\mathcal{D} \cup \mathcal{D} = \mathcal{D}) \geq 1 - \delta$ may permit limited deletion support through probabilistic cleanup of stale state. The space lower bounds for structures simultaneously achieving $\eta$-deletion and $\delta$-composability remain an open theoretical question. Practical systems must evaluate whether such approximate guarantees suffice for their workloads, as the hybrid approach incurs concrete costs: maintaining two structures doubles memory overhead, requires coordination between structures when elements are both deleted and aggregated, and complicates failure recovery protocols that must restore consistency across both oracles.
