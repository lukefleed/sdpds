Disaggregated systems separate compute, memory, and storage into independent network-attached services \cite{Grant2025CuckooFC, Langlet2025SketchDA}. Compute workers are instantiated for short durations, executing stateless functions without persistent local state \cite{Zaharia2012ResilientDD, Huang2016TowardHD}. Storage and memory servers maintain persistent state accessed over network interconnects. This separation creates an impedance mismatch: state-dependent computation must query remote state over network links with latencies orders of magnitude higher than local memory access \cite{Grant2025CuckooFC}. Every validation query that requires consulting remote state introduces a network round-trip cost that dominates application latency \cite{Chang2006BigtableAD, Tarkoma2012TheoryAP}.

The mismatch manifests in two operations. The first is membership testing: determining whether an element exists in a remote set before executing read-modify-write operations \cite{Tarkoma2012TheoryAP}. A compute worker querying a deterministic key-value store incurs a network round-trip for every validation \cite{Mosharraf2021ImprovingLA, Dayan2021ChuckyAS}. The second is cardinality estimation: computing the number of distinct elements in a partitioned dataset \cite{Harmouch2017CardinalityEA}. An exact \texttt{COUNT(DISTINCT)} query requires a shuffle operation that transmits all unique elements to a central reducer \cite{Zaharia2012ResilientDD}. Communication cost scales with dataset cardinality, rendering interactive analytics over petabyte-scale data infeasible \cite{Heule2013HyperLogLogIP}.

Resolving this mismatch requires compact summaries that can be queried locally or transmitted with fixed cost independent of dataset size. The summary must synchronize with a dataset that undergoes insertion and deletion. When aggregating information across partitions, the summary must support combination operations that produce results identical to processing the complete dataset.

Probabilistic data structures provide queryable summaries with sublinear space complexity. A Bloom filter occupies space proportional to the logarithm of the target false positive rate, independent of element size \cite{Broder2004NetworkAO}. A HyperLogLog sketch estimates cardinality using fixed space regardless of dataset size \cite{Flajolet2007HyperLogLogTA}. These structures trade bounded error probability for space efficiency.

The value of probabilistic structures in disaggregated systems derives from two properties. Dynamic mutability enables structures to delete elements, maintaining synchronization with datasets that undergo explicit deletion operations \cite{Fan2014CuckooFP}. Algebraic composability enables structures to combine partial summaries through operations that are commutative, associative, and idempotent, supporting distributed aggregation without data movement \cite{Heule2013HyperLogLogIP}.

These properties address orthogonal deployment constraints. Mutability resolves state synchronization with evolving datasets. Composability resolves distributed aggregation without shuffling raw data. The properties impose conflicting requirements on internal state representation. Mutability requires element-level information retention to enable targeted deletion. Composability requires information loss through commutative aggregation operations that discard element identities.

This tension explains why specific structures succeed in specific distributed contexts. Cuckoo Filters provide mutability but not composability, enabling co-partitioned membership testing. HyperLogLog provides composability but not mutability, enabling hierarchical cardinality aggregation. The framework establishes which deployment constraints each property addresses and which architectural patterns each property enables.
