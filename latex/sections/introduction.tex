\section*{Introduction}
\label{sec:introduction}

The architectural paradigm for large-scale systems is shifting from co-located compute and storage towards resource disaggregation \cite{Grant2025CuckooFC, Langlet2025SketchDA}. We observe that current distributed systems, including high-performance key-value stores and data analytics platforms, increasingly rely on disaggregated memory and storage servers accessed over the network . In this model, compute, memory, and storage function as independent, network-attached services. The consequence of this separation is that the network fabric, which typically uses high-speed interconnects like RDMA, becomes the de-facto system backplane \cite{Grant2025CuckooFC, Langlet2025SketchDA}.

We note a parallel movement in computational models toward ephemeral and stateless functions \cite{Zaharia2012ResilientDD, Huang2016TowardHD}. These compute workers are instantiated for short durations, executing specific business logic without maintaining persistent local state. In a fully disaggregated architecture, this confluence of trends creates a fundamental tension. High-performance, state-dependent computation must execute on stateless, ephemeral workers over a network-centric substrate \cite{Grant2025CuckooFC}. A key challenge emerges because access latency to remote memory is an order-of-magnitude slower than access to local DRAM, even when using modern RDMA techniques \cite{Grant2025CuckooFC}. Every decision that requires consulting remote state, even for simple data validation, introduces a network round-trip cost that now dominates application latency \cite{Chang2006BigtableAD, Tarkoma2012TheoryAP}.

This architectural tension manifests as an impedance mismatch between the need for low-latency state access and the physically distributed nature of disaggregated resources. We identify two canonical operations where this mismatch imposes unsustainable communication costs. The first is the validation of preconditions for state modification, a primitive operation in distributed databases known as set membership testing \cite{Tarkoma2012TheoryAP}. A compute function must determine if an element exists in a remote set, often to avoid a costly read-modify-write operation on a non-existent key \cite{Mosharraf2021ImprovingLA, Dayan2021ChuckyAS}. A deterministic query to a remote key-value store for every such validation check introduces a network round-trip, a cost that nullifies the performance benefits of local computation.

The second manifestation is the execution of large-scale analytical aggregations, such as cardinality estimation \cite{Harmouch2017CardinalityEA}. In a data-parallel framework, an exact \texttt{COUNT(DISTINCT)} query requires a shuffle operation that transfers all unique data elements across the network to a common set of reducers for final aggregation \cite{Zaharia2012ResilientDD}. The communication cost of this operation is proportional to the dataset cardinality, rendering interactive-speed analytics over petabyte-scale data architecturally infeasible \cite{Heule2013HyperLogLogIP}. We argue that what is required are mechanisms that project a compact, queryable, and composable representation of the remote state directly to the compute layer, thereby bridging this impedance mismatch.

We propose that Probabilistic Data Structures (PDS) provide this architectural bridge. These structures function as compact summaries of remote state that can be efficiently transmitted to, maintained at, or queried by compute workers. We argue that their architectural value in modern systems derives not only from their sub-linear space complexity, but more critically from two properties: dynamic mutability and algebraic composability.

Dynamic mutability, specifically the ability to delete elements from a probabilistic oracle, allows the summary's state to remain synchronized with a live, changing dataset \cite{Fan2014CuckooFP}. This capability is a prerequisite for their use beyond static filtering, enabling accurate membership semantics in systems where the lifecycle of data includes explicit deletion and garbage collection \cite{Mosharraf2021ImprovingLA, Dayan2021ChuckyAS}. Algebraic composability, in contrast, enables the decentralized aggregation of summaries computed over distributed data partitions through well-defined, order-independent operations \cite{Heule2013HyperLogLogIP}. This property allows a system to perform parallel reductions without a central coordinator or the movement of raw data. We will demonstrate that it is the synthesis of these properties with low space overhead that elevates a specific class of PDS from tactical optimization to a strategic architectural enabler.
